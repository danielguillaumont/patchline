# FIRST EPSS daily ingestion (P2.2)

The **bulk** source is FIRST's current gzip CSV: `https://epss.empiricalsecurity.com/epss_scores-current.csv.gz`. This URL redirects; the downloader follows redirects. The FIRST API is for lookup and must not be used to enumerate the whole population. FIRST requests attribution; EPSS scores are generated by Empirical Security.

Run `uv run --locked python -m patchline ingest --source epss`. The command downloads the complete feed, validates the gzip stream, metadata line (`model_version` and UTC `score_date`), exact CSV header, CVE uniqueness and syntax, finite probability/percentile within [0,1], and a nonempty population. Validation is streaming over decompressed lines; the input gzip is archived **unchanged**, preserving decimal precision for future warehouse loading. It limits compressed size to 30 MiB, decompressed size to 120 MiB, and records to 2 million. Exceeding the limits is a failure, not a partial success.

Snapshots are stored under ignored `data/raw/epss/<compressed SHA-256>/` as `scores.csv.gz` and `manifest.json`. The manifest is the completion marker. Repeated identical ingestion verifies the prior manifest and archived bytes before returning `skipped_existing`; a failure does not overwrite a published archive. An interrupted initial write may leave an incomplete directory without a manifest; rerunning identical valid data can finish it. Do not manually edit source or manifests. Investigate corrupted snapshots before taking recovery action.

Source `score_date` is not a local retrieval date. A model-version boundary is not a like-for-like trend: preserve and display model version for each score date. EPSS scores are not confirmed exploitation and percentiles are rankings, not probabilities.

The offline tests use miniature **synthetic** datasets. A full live download, archive verification, and repeat-run validation are required separately before merging this slice.
